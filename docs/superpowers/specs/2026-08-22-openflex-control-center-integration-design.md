# OpenFlex 控制中心综合集成设计

## 背景

当前 `openflex_gui` 是基于 PyQt5 的 ROS 2 桌面控制台，负责 CAN、整机
bringup、VR 遥操作和传感器查看。`openflex_manager` 是基于 PySide6 的独立
硬件管理应用，包含头部、双臂、升降柱和底盘的连接、使能、标定、运动及
状态监控。部署中心目前只有占位内容。

本设计将两套界面合并为一个控制中心，同时接入安装构建脚本，并保留现有
ROS 2 控制流程。最终用户只启动一个应用。

## 已确认目标

- 左侧导航包含“整机控制”“电机管理”“传感器”“部署中心”。
- 电机管理是真正嵌入的页面，不启动第二个窗口。
- 电机管理完整覆盖头部、双臂、升降柱和底盘现有功能。
- 整机控制左栏按 CAN、电机状态、整机启动、VR 遥操作从上到下排列。
- 运行诊断独占整机控制页面右栏的完整高度。
- 顶栏提供日间/夜间主题切换按钮，并保存用户选择。
- 电机直连维护、ROS 2 整机控制和系统部署之间实施严格互斥。
- 部署中心接入 `install_openflex_drivers_and_build.sh` 的受支持模式。
- 不丢失当前 `openflex_gui` 和 `openflex_manager` 中已有的用户修改。

## 非目标

- 不在第一阶段改变 ROS 2 launch 文件和底层电机协议。
- 不重新实现 `openflex_driver` 已提供的硬件访问能力。
- 不允许部署中心静默获取管理员权限。
- 不把图形界面的停止按钮描述成硬件急停的替代品。

## 技术方向

整个应用统一为 PySide6。将约 1600 行的 `openflex_gui` 从 PyQt5 迁移到
PySide6，比把 `openflex_manager` 约 9800 行的界面和控制器迁移到 PyQt5
风险更低。最终只有一个 `QApplication`、一个 `QMainWindow` 和一个 Qt 事件
循环。

`openflex_gui` 继续作为 ROS 2 `ament_python` 包及桌面入口。
`openflex_manager` 的业务控制器逐步变成 `openflex_gui` 可导入的模块；其
`main.py` 在过渡期仍可独立运行，但不再是控制中心的集成方式。

## 页面结构

### 顶栏

顶栏从左到右显示应用图标、名称、真实系统健康状态、平台信息和主题按钮。
健康状态由运行状态协调器计算，不再固定显示“控制台就绪”。主题按钮使用
太阳和月亮图标表达当前可切换的模式，悬停提示分别为“切换到夜间模式”和
“切换到日间模式”。

主题默认沿用当前日间视觉；用户切换后写入本地设置，重启后恢复。两套主题
覆盖页面背景、边框、文字、状态色、按钮、表格、滚动条、对话框和日志区，
不能只反转背景颜色。

### 整机控制

页面采用左右两列可调整布局：

```text
┌──────────────────────────────┬──────────────────────────────┐
│ 1. CAN 总线                  │                              │
│ 2. 电机状态                  │         运行诊断             │
│ 3. 启动整机控制              │         完整右栏             │
│ 4. VR 遥操作                 │                              │
└──────────────────────────────┴──────────────────────────────┘
```

VR 卡片移入左栏并位于整机启动步骤下方。其“VR 控制底盘速度”保持默认勾选。
右栏只放运行诊断，随窗口高度扩展。页面宽度不足时使用滚动区域和受约束的最小
宽度，不让按钮或文字互相覆盖。

### 电机管理

页面顶部显示维护模式状态、CAN 状态和安全说明，下方使用四个标签页：

1. 头部：连接、使能/失能、主动/被动设零、回零、步进控制和状态监控。
2. 双臂：左右臂选择、使能/失能、设零、回零、关节步进和电机状态表。
3. 升降柱：连接、模式切换、点动、目标位置、快速停止、设零、回原点和状态。
4. 底盘：连接、使能、整车运动、单电机测试、转向标定、停止和状态监控。

不把旧 `OpenFlexMainWindow` 嵌套进主窗口。旧窗口中的四个页面抽取为
`MotorManagementPage(QWidget)`，控制器依赖该页面公开的控件接口。CAN
状态对话框、电机检查对话框、翻译、输入限制和现有控制器继续复用。

### 传感器

保留 RealSense ROS 2/RViz2、RealSense Viewer 和 Livox/RViz2 入口。为每个
设备增加未检测、可用、运行和异常状态，启动前检查可执行文件、配置文件和
设备节点。运行中的进程仍由统一进程管理器负责停止。

### 部署中心

部署中心通过受控的 `QProcess` 调用现有脚本，不复制脚本中的安装逻辑。页面
提供以下任务：

- 环境预检和 `--dry-run` 预览。
- 完整安装 `--openflex`。
- 工作空间编译 `--compile`。
- KCAN 驱动安装 `--kcan`。
- VR 软件安装 `--vr`。
- 相机配置 `--camera`。
- 雷达配置 `--lidar`。
- 源码同步 `--sync-source`。

桌面快捷方式暂不接入部署中心，也不修改用户当前桌面入口。

每次只运行一个部署任务。页面展示当前阶段、已运行时间、实时输出、成功或
失败结果以及取消按钮。涉及系统安装、驱动或设备配置的任务必须先显示操作
摘要并二次确认。取消时先发送 SIGINT，超时后终止进程组。

`--compile` 和所有 `--dry-run` 任务由 GUI 内部 `QProcess` 执行。实际安装、
驱动、源码同步及设备配置任务使用 GNOME 终端运行，以便 sudo 和脚本自身的
交互提示直接由终端安全处理；控制中心不读取或保存密码。终端任务通过临时
日志、PID 和退出状态文件把输出与结果同步回部署中心。

## 模块边界

为避免继续扩大单个 `main_window.py`，控制中心按职责拆分：

- `main_window.py`：窗口外壳、导航、顶栏和关闭协调。
- `pages/control_page.py`：整机控制布局及用户事件。
- `pages/motor_management_page.py`：四类电机控制的统一页面容器。
- `pages/sensors_page.py`：传感器入口和设备状态。
- `pages/deployment_page.py`：部署任务选择、确认、进度和输出。
- `services/runtime_coordinator.py`：运行模式、互斥规则和全局状态。
- `services/process_manager.py`：所有 ROS、传感器和部署子进程的生命周期。
- `services/deployment_runner.py`：安装脚本参数白名单和部署状态解析。
- `services/theme_manager.py`：日间/夜间主题加载与持久化。
- `services/settings.py`：非敏感用户设置。
- `motor/`：从 `openflex_manager` 迁入的控制器、对话框和适配代码。

页面不直接拼接任意 shell 命令。进程管理器接收预定义任务和经过验证的参数。

## 运行状态与互斥

运行协调器维护四种顶层状态：

- `IDLE`：没有硬件控制或部署任务。
- `ROS_CONTROL`：整机 bringup 或 VR 正在运行。
- `MOTOR_MAINTENANCE`：电机管理器已连接任何硬件。
- `DEPLOYING`：安装、驱动、配置或构建任务正在执行。

状态转换规则：

- `ROS_CONTROL` 禁止电机直连、标定和部署。
- `MOTOR_MAINTENANCE` 禁止启动整机、VR 和部署。
- `DEPLOYING` 禁止 CAN、电机、整机、VR 和传感器启动操作。
- 从维护模式退出时，按停止运动、失能电机、关闭设备连接的顺序清理。
- 停止整机时先停止 VR，再停用底盘控制器，再结束 bringup 及其附属进程。
- 关闭 GUI 时执行同一套有超时的清理流程，不能无限阻塞界面。

进入有冲突的操作时，按钮保持禁用并显示具体原因，不自动替用户关闭另一种
控制模式。

## 数据与日志流

所有后台线程、ROS 进程和部署任务通过 Qt 信号发送结构化事件：来源、级别、
时间、消息和可选进度。日志视图限制内存中的最大记录数，并支持来源和级别
筛选、清空及导出。

应用启动时检查 CAN、ROS 2 节点、controller manager 和已知子进程，尽可能
恢复真实状态。无法确认所有权的外部进程只显示为“外部运行”，控制中心不在
未经确认时终止它。

## 配置与权限

- 工作空间路径通过安装位置、环境变量和用户设置解析，不写死发行目录。
- CAN 映射、VR 底盘默认值、RViz 开关和传感器配置进入统一设置。
- 不在 YAML 或源码中保存 `sudo` 密码。
- 需要提权时使用系统 `sudo`/polkit 提示，并将密码输入留给系统。
- 部署任务只允许调用固定脚本和固定参数集合。
- 现有 `openflex_manager/config/app_settings.yaml` 中的敏感字段在迁移时删除。

## 错误处理

- 缺少文件、依赖、设备或 ROS 包时，在执行前阻止操作并列出缺失项。
- 子进程异常退出时恢复按钮状态，保留退出码和最后日志。
- 硬件连接失败不阻止应用打开，但对应控制页进入异常状态。
- 长任务不在 GUI 主线程运行。
- 关闭和取消采用 SIGINT、等待、终止的分级流程。
- 电机运动和标定操作沿用现有确认与限位检查。

## 测试与验收

### 自动化测试

- PySide6 迁移后，现有 GUI 页面和按钮行为测试全部通过。
- 主题切换覆盖初始模式、两套样式、图标和重启持久化。
- 整机控制布局验证 VR 位于左栏下方、日志独占右栏。
- 运行协调器覆盖所有允许和禁止的状态转换。
- 进程管理器覆盖启动失败、正常退出、SIGINT 和超时终止。
- 电机管理各控制器使用假硬件测试信号绑定、状态更新和关闭清理。
- 部署 runner 只接受白名单任务，并验证 dry-run、取消和失败状态。

### 无硬件验收

- `colcon build --packages-select openflex_gui` 成功。
- 从 `install/setup.bash` 启动控制中心成功。
- 1024x700、1360x820 和更大桌面尺寸无文字、按钮或页面重叠。
- 日间和夜间主题均完成截图检查。
- 关闭应用后没有由控制中心启动的遗留子进程。

### 实机验收

按 CAN、头部、单臂、双臂、升降柱、底盘、整机 bringup、VR、传感器顺序
逐项验证。维护模式与 ROS 控制的互斥必须先通过，再允许进行运动验证。部署
中心先运行 dry-run，再逐项执行低风险任务，最后才测试驱动和完整安装。

## 分阶段交付

1. **界面基础阶段**：迁移 PySide6，完成整机控制新布局和日/夜主题。
2. **电机管理阶段**：嵌入四类控制页面，接入控制器和维护模式清理。
3. **部署中心阶段**：接入安装脚本、预检、进度、取消和权限提示。
4. **收尾阶段**：真实健康状态、统一设置、日志筛选、状态恢复和全量验证。

每一阶段都必须保持应用可启动、可构建，并通过该阶段新增的自动化测试后再
进入下一阶段。
