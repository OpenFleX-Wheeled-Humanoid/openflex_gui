# OpenFlex 发售版 GUI 改版设计

## 目标

在现有 ROS 2 Python 包 `openflex_gui` 内重做 PyQt5 界面，使其采用已经确认的 v13 控制中心布局，同时保留现有 CAN、电机检查、整机 Bringup、VR、相机、雷达、电池后台启动和退出清理逻辑。

## 范围

- 修改发售版源码 `openflex_gui/main_window.py`。
- 保留现有 PyQt5 与 ROS 2 包结构，不引入 Qt6。
- 不修改任何 ROS launch 参数、CAN helper、传感器命令或进程停止顺序。
- 不显示电池监控面板；整机启动时现有电池节点联动逻辑继续保留。
- 保留日志最大 3000 块的限制，避免日志无限增长。
- 部署中心在基础版本中只显示说明，不执行安装或构建脚本。

## 页面结构

窗口使用 1360 x 820 的初始尺寸和 1024 x 700 的最小尺寸。

1. 顶部栏：OpenFlex 图标、控制中心标题、运行环境状态和 ROS 2/KCAN 标识。
2. 左侧导航：整机控制、传感器、部署中心。
3. 整机控制：左侧为一个贯通的流程面板，依次放置 CAN 总线、电机状态、整机控制；右侧放置 VR 遥操作和运行诊断日志。
4. 传感器：保留 RealSense ROS2、RealSense Viewer 和 Livox MID360S 的现有按钮。
5. 部署中心：基础占位页，明确后续接入脚本，不提供无效操作按钮。

## 交互和状态

- 所有现有按钮属性名保持不变，后台函数无需改名。
- 左侧导航只切换 `QStackedWidget` 页面，不启动后台操作。
- 状态圆点继续由现有 `StatusDot.set_state()` 更新。
- 顶部“检查全部电机”和“安全停止”分别复用 `_on_check_status()` 与 `_on_stop_bringup()`。
- 日志仍通过现有线程安全信号写入，颜色与最大块数保持有效。
- 关闭窗口时继续执行底盘失能、进程组 SIGINT、超时强制退出。

## 视觉规则

- 背景 `#eef2f7`，面板白色，边线 `#d4deea`，主色 `#1e5bd3`。
- 卡片圆角不超过 7 px，避免浮夸阴影和大面积渐变。
- 控制顺序使用编号圆标、状态点和明确的主/次按钮。
- 窄窗口下控件使用滚动区域，按钮和文字不能重叠。

## 验收

- 程序在 `QT_QPA_PLATFORM=offscreen` 下可创建并关闭主窗口。
- 默认页面为整机控制，导航可以切换三个页面。
- 原有后台按钮属性均存在且信号连接不丢失。
- 日志最大块数为 3000。
- Python 编译检查和 UI 自动测试全部通过。
- 生成离屏截图，确认窗口非空且主要面板尺寸有效。
