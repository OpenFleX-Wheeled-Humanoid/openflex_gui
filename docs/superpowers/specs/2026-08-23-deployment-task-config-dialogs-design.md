# 部署任务专用配置界面设计

## 目标

删除部署中心底部的通用“任务输入框”，改为只有在任务确实需要参数时才显示对应的专用配置对话框。用户在对话框中完成选择或填写后，GUI 将参数转换为安装脚本可识别的非交互参数或预置输入，并启动原有任务流程。

## 现状与约束

- 目标代码只在 `Release-version/openflex_ws`，不修改旧工作区。
- 现有部署卡片和 `DeploymentRunner` 负责选择任务、显示日志和管理进程；这部分行为继续保留。
- 安装入口是 `OpenFleX/install_openflex_drivers_and_build.sh`。本次不重写脚本的业务逻辑。
- 脚本当前交互项包括：VR 类型与 USB 连接确认、四个相机序列号、雷达主机 IP 尾段与设备 SN 尾段、源码同步菜单选择，以及若干 sudo/Enter 确认。
- 密码不进入 GUI 字段、不写入日志、不保存到配置文件；系统权限授权通过现有终端桥接流程完成。

## 方案

部署中心保留现有任务卡片，点击“执行”后按任务类型分流：

| 任务 | 新界面 | 执行策略 |
| --- | --- | --- |
| 环境安装 | 无参数确认对话框 | 确认后直接执行，权限提示在日志/授权流程中处理 |
| 工作空间编译 | 无参数确认对话框 | 确认后直接执行 |
| KCAN 驱动 | 无参数确认对话框 | 确认后直接执行，保留脚本的卸载确认 |
| VR 软件 | VR 设备单选（Pico/Quest）+ USB 已连接确认 | 将选择转换为脚本选择输入；未确认连接时不启动 |
| 相机配置 | 右腕、左腕、头部、底盘四个序列号输入框，预填当前配置，空值表示保持不变 | 校验序列号字符后提交四项输入 |
| 雷达配置 | 主机 IP 尾段、雷达 SN 尾段输入，显示完整 IP 预览，并提供“已完成网口设置”确认 | 校验 0-255 范围后提交 |
| 源码同步 | 安装脚本 1-9 菜单的下拉选择，默认“仅下载/更新源码” | 将菜单项转换为脚本选择输入 |

无参数任务使用轻量确认框；有参数任务使用同一套 `QDialog` 基类和任务专用表单。对话框取消时不启动任务，表单校验失败时保留输入并给出字段级错误。

## 组件边界

### `deployment_config_dialog.py`

新增模块，包含：

- `DeploymentConfigDialog`：根据任务 ID 创建对应表单，返回结构化配置字典。
- `CameraConfigForm`、`LidarConfigForm`、`VrConfigForm`、`SourceSyncConfigForm`：只负责字段、默认值和校验，不启动进程。
- 表单输出使用稳定键名：`vr_device`、`vr_connected`、`camera_serials`、`host_ip_last`、`lidar_sn_last`、`source_choice`。

### `main_window.py`

- 移除 `deployment_input`、`btn_deployment_send`、输入行布局和 `_send_deployment_input`。
- 在 `_on_deployment_run` 中先调用配置对话框；得到配置后才调用 runner。
- 任务运行状态只控制卡片按钮和停止按钮，不再控制通用输入框。

### `deployment_runner.py`

- 保留现有 PTY/日志/进程生命周期逻辑。
- 增加一个明确的 `input_lines` 或等价参数，用于按任务一次性写入预收集的输入序列。
- 输入写入顺序固定并覆盖测试；不允许任意文本从主窗口直接注入。

### 测试

- 对话框单元测试：默认值、取消、必填校验、数值范围和结构化结果。
- runner 测试：每个交互任务的输入序列与脚本菜单顺序一致；无参数任务不写入输入。
- GUI 测试：通用输入控件不存在；点击相机/雷达/VR/源码卡片会进入对应配置流程；取消不会启动 runner。
- 保留并运行现有 PTY 集成测试，确保 sudo 或脚本提示仍可在嵌入式终端中工作。

## 错误与安全处理

- 所有输入在 GUI 提交前验证；脚本仍会做最终校验，失败日志显示在部署日志区。
- 对话框只保存在内存中的当前任务配置，关闭后释放；不写入日志。
- 任务启动失败、用户取消和脚本非零退出分别显示明确状态，不弹出新的外部终端。
- sudo 密码永远不经过普通文本输入控件；如果系统授权不可用，日志显示授权失败并允许停止任务。

## 验收标准

1. 部署中心界面不再出现通用任务输入框或“发送”按钮。
2. 点击需要参数的任务时，用户只能看到与该任务相关的字段。
3. 取消配置不会启动脚本；合法提交能按脚本原有顺序完成交互。
4. 环境、编译、KCAN 等无参数任务仍可一键执行。
5. 全部 GUI/runner 测试通过，且构建后的 ROS 2 包可正常启动。
